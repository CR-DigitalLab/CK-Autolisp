# YokeruText 1.0.1 の lispcheck 検証結果（2026-09-27）

AutoCAD の代わりに `tools/lispcheck/lispcheck.py`（簡易シミュレータ）で動かした結果です。
AutoCAD 実機での確認の前に、明らかな不具合を見つけるためのものです。

## 実行した場面

| 場面 | 入力 | 結果 |
|---|---|---|
| 図面全体(A) → 確定 | 選択なし → A → Enter | ○ 対象 43・重なり 36 → 移動 34（引出線 21）・逃げ場なし 1。エラーなし |
| 確認中に Esc | 選択なし → A → Esc | ○ 「中止しました。変更は元に戻しました。」図面は元どおり（※1） |
| 確認で「元に戻す(U)」 | 選択なし → A → U | ○ 図面は元どおり（※1） |
| 選択なし → 終了 | Enter → Enter | ○ 何も変わらずに終了 |
| 選択中に Esc | Esc | ○ 「中止しました。」で安全に終了 |
| 設定 → 初期値 | YKS → R → Enter | ○ エラーなし |
| 区画10 固定画層 FIX | 設定 FixLay=FIX で実行 | ○ 動かない（固定 1） |
| 区画15 ハッチ OFF / ON | 初期設定 / UseHat=1 | ○ OFF：動かない。ON：ハッチの外へ出て引出線 1 本 |
| すべての場面 | ― | ○ システム変数の変え忘れなし |

※1 残る「変更 33」は、lispcheck が文字に回転角 0 度の記録を書き足しただけで、位置は元どおりです。

## 見つかって直した不具合

| 内容 | 対応 |
|---|---|
| 回転角の記録が省略された文字（0度の文字でよくある）を「対象外」にしていた | 回転角が無ければ 0 度とみなす（1.0.1） |
| ハッチ(H)ON でも、ハッチの内側にある文字を重なりと判定しなかった（外形の線だけを見ていた） | ハッチの外形の四角の内側すべてを障害物にする（1.0.1） |
| テスト図面の区画15のハッチが大きすぎて、初期設定の距離では外へ出られなかった | ハッチを小さくした |

あわせて lispcheck 側の誤り（`entmakex` が図形名ではなくデータを返していたため、引出線を消せなかった）も直しました（lispcheck 0.1.1）。

## lispcheck では確かめられないこと（AutoCAD で確認）

- マルチテキスト（区画04・12）：lispcheck は大きさを計算しないため対象外になる → 区画04 の動き、区画12 の背景マスク
- 緑の矢印・赤枠の表示（画面表示は再現されない）
- 文字の幅（概算）、スプライン（折れ線で近似）
- UCS を回転したとき（区画19 ①）
- AutoCAD の Undo（`U`）で 1 回で戻るか

# ChikoLispCheck（チコ リスプ チェック）

AutoLISP を note などで公開する前に、チコさんのルールが守れているかを点検するツールです。Python ファイル1つで、画面（GUI）付き。追加のインストールは不要です（Python の標準機能だけ）。

![画面](test/結果/画面.png)

## 使い方

1. Windows に Python（3.8 以上。python.org の標準のもの）を入れておく。
2. `ChikoLispCheck.py` をダブルクリック → 窓が開く。
   - LSP ファイルを `ChikoLispCheck.py` の上にドラッグ＆ドロップしても開けます（すぐにチェックします）。
   - 後ろに出る黒い窓が気になるときは、拡張子を `.pyw` に変えてください。
3. ［ファイルを選ぶ］で LSP を選ぶ（複数でも可）→ 自動でチェックします（［チェック］でやり直し）。
4. 結果を見る。
   - 一番上に全体の判定：**公開OK／確認してから／直してから**
   - 各項目：**○ 合格　△ 要確認（目で確かめる）　× 不合格（直してから公開）**。何行目か・なぜか・どう直すかを表示します。
5. ［記事用の文章をコピー］で、note に貼れる紹介文のひな形をコピーできます（「記事用の文章」タブで中身を見られます）。
6. ［結果を保存］で、結果と記事用の文章をテキストファイルに保存できます。

コマンドで使う場合：`python ChikoLispCheck.py --cli ファイル.lsp [ファイル2.lsp ...]`

## チェックする項目

| 番号 | 項目 | × になるとき | △ になるとき |
|---|---|---|---|
| A1 | AutoCAD LT 2024 以降で使えるか | Express Tools（acet-）、Excel などの外部連携、VBA、3D ソリッド、LT に無いコマンドを使っている | ― |
| A2 | 環境に左右されないか | ― | コマンド名・オプションに `_` が無い、スナップの影響を受けそう、決め打ちのフォルダの場所、vla-SendCommand |
| B1 | 文字コードが ANSI か | UTF-8 で保存している／ファイルを UTF-8 で書き出している | ― |
| B2 | ファイルの先頭の説明 | ― | 名前・使い方が見当たらない（バージョンは初版なら不要。2回目の公開＝ver2 から付ける。無いときは一言添えるだけ） |
| B3 | 読み込んだときのメッセージ | ― | コマンド名を表示していない |
| C1 | ショートカットがあるか | 正式なコマンドに短い別名が無い | ― |
| C2 | AutoCAD 標準と重なっていないか | 標準のコマンド名・短縮名（acad.pgp）と同じ名前 | ― |
| C3 | 結果の通知 | ― | 結果を表示していないコマンドがある |
| C4 | 静かに終わる | ― | 最後が `(princ)` でない |
| D1 | エラー時の後始末（*error*） | *error* が無い（図面・システム変数を変える場合）、ローカルにしていない、ファイル全体で定義している | *error* の中で command を使っている |
| D2 | システム変数を元に戻すか | 変えているのに、エラーのときに戻す処理が無い | 変える前の値を覚えていないように見える |
| D3 | Undo グループ | 図面を変えるのに無い／閉じていない／エラーのときに閉じていない | ― |
| D4 | Esc・選択なしで落ちないか | ― | 選択・入力の結果を空か確かめずに使っているように見える |
| D5 | ほかの LISP とぶつからないか | ― | ローカル宣言されていない変数、印の無い関数名（例：dtr） |
| E1 | 個人情報・社内情報 | メールアドレス、ユーザー名入りのフォルダ | ネットワークの場所（社内サーバー名など） |
| E2 | 試し書きの残り | ― | TODO・デバッグなどのコメント、どこからも使われていない関数 |
| E3 | 作者・利用条件の表記 | ― | 先頭に作者・利用条件（再配布の可否・免責など）が無い |

- 機械で確実に言えることだけを ×、迷うものは △ にしています。
- 括弧の対応など「動くかどうか」は、ここでは見ません（lispcheck で確認）。
- ユーザーが作った関数の中身もたどって判定します（例：*error* から呼んだ関数でシステム変数を戻していれば OK）。
- A2 のスナップ、D2〜D4 は「書き方」から推測する簡易な判定です。△ のときは目で確かめてください。
- C2 の標準の名前は、主なコマンドと標準の短縮名だけです（すべてではありません）。

## 記事用の文章（ひな形）

LSP の中身から自動で作ります：概要（先頭のコメント）、コマンドとショートカット、動作環境（LT 2024 以降で使えるか）、システム変数を変えるか、Undo 1回で戻せるか、文字コード、読み込み方。例：[記事用の文章の例](test/結果/記事用の文章の例.txt)

## 動作確認

- わざとルール違反を入れた見本 [見本_ルール違反.lsp](test/見本_ルール違反.lsp)（UTF-8 で保存）→ 「直してから（○0 △9 ×8）」。すべての違反を見つけた：[結果](test/結果/見本のチェック結果.txt)
- ルールを守った見本 [見本_ルール順守.lsp](test/見本_ルール順守.lsp)（ANSI）→ 「公開OK（○17）」
- チコさんのツール（ProjectSet・YokeruText・SaveVersion）→ どれも「確認してから（△1：作者・利用条件の表記が無い）」：[結果](test/結果/チコさんのツールのチェック結果.txt)
- チコさんの note で無料配布中の LISP 22本（2026-09-29 にダウンロード。ZIP の中はスクリプトと別ソフト、体験版の .fas は中身を読めないため対象外）→ [結果](test/結果/noteのLISPのチェック結果.txt)。× の指摘はすべて中身と照らして正しいことを確認（LSP そのものは再配布禁止のため保存していない）
- 画面は Linux の仮想画面で表示を確認（[画面.png](test/結果/画面.png)）。Windows での見た目はチコさんに確認してもらう。

## 更新履歴

- 1.0.3（2026-09-29）バージョンの表記が無くても △ にしないようにした（初版では不要、ver2 から付けるというチコさんの方針に合わせた）。
- 1.0.2（2026-09-29）note の LISP 22本で試して見つかった誤りを修正：ブラウザを開く・システム変数の一覧を書き出すだけのコマンドを「図面を変える」と数えていた／図面もシステム変数も変えないコマンドにも *error* を求めていた／「現在の画層を 0 にする」のように変えること自体が目的のシステム変数まで × にしていた（一時的に変えるものだけ ×、ほかは △）／元の *error* を覚えて戻す古い書き方を × にしていた（△ に）。
- 1.0.1（2026-09-29）note の LISP で試して見つかった誤りを修正：本体を呼んだあと (princ) を付けたショートカットを見落としていた／「著作権」の表記を作者として数えていなかった／結果の通知が「〜します」の前置きだけでも合格にしていた（件数や「〜しました」を見るようにした）。
- 1.0.0（2026-09-29）最初の版。
